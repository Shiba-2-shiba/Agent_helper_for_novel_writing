# Compaction Policy (Common)

## セッション整理のトリガー

以下のいずれかが発生したとき、セッション終了とみなして圧縮を実施する：

- ユーザーが明示的に「終了」「セッション終わり」と宣言したとき
- タスクの主要成果物（ファイル・出力）がすべて完成したとき
- 会話が自然に一区切りついたとき（次のリクエストが明確でない）

---

## 基本方針

- Local LLM 向けの強圧縮ではなく、Agent アプリ前提の再開品質重視で運用する
- 単に短くするのではなく、次回の作業品質に効く文脈を残す
- 文体契約、未解決事項、次回着手点、直近の重要判断は必ず保持する

---

## `session_notes.md` の運用ルール

`session_notes.md` は「直近の再開に必要な情報」を保持する主メモとする。

推奨構成:

```
## [YYYY-MM-DD] セッション要約

### 新事実
- （このセッションで判明した重要な情報）

### 決定事項
- （このセッションで行った重要な判断）

### 未解決
- （次セッションに持ち越す問題・疑問）

### 次アクション
- （次にやること）
```

保持方針:

- 直近 3〜5 セッションは詳細を残してよい
- それより古い詳細は、要点だけを残すか `session_archive.md` へ退避する
- 完了済みで再開に不要な細かな経緯は削ってよい
- ただし、改稿理由、方向転換理由、読後感の狙いは削らない
- `session_notes.md` は、原則として「最新の要約 1 件 + アクティブ案件メモ + 共通メモ」程度に収める
- 低優先度になった案件の詳細は、要約して `session_archive.md` へ移す

### 文体契約保全ルール（必須）

- 圧縮時に **視点・語尾・文体トーン** を削除しない
- 文体に関する新決定は必ず `global_notes.md` の「文体契約」へ昇格する
- `session_notes.md` には文体変更の理由だけを残し、契約本文は `global_notes.md` を正本とする

---

## `session_archive.md` の運用ルール

- 長い経緯を保持したい場合は、古い詳細を `session_archive.md` に移す
- `session_archive.md` は、通常の再開ではなく、過去判断の再確認が必要なときだけ参照する
- `session_notes.md` からは、再開に必要な要約だけを残す
- パイロット案件や検証済みの補助情報は、現行の主タスクから外れた時点で `session_archive.md` へ移してよい

---

## `global_notes.md` への昇格基準

`session_notes.md` の内容を `global_notes.md` に移すのは：

- **昇格すべきもの**: プロジェクト全体に永続的に影響する事実・制約・決定
  - 例: 「このプロジェクトは Python 3.11 限定」「本文の一人称は『俺』」
- **昇格しないもの**: セッション固有の一時情報・やり取りの詳細・完了したタスク

---

## ログへの記録

圧縮時に合わせて実施：

- 重要な判断 → `decisions_log.md` に追記
- ファイル変更 → `change_log.md` に追記
