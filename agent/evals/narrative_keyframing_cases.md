# 選択的主観素材の短文評価プロトコル

Protocol status: `not_run`（このテンプレート自体は実施記録ではない）。実行時は別の記録へ実際の日時・素材・本文・CLI結果を保存し、実施済みと未実施を分ける。

## 共通条件

- 作者の作品を変更せず、隔離した新規projectの短い日本語sceneを使う。文字数帯と明示POVを設定する。
- 対象sceneのprepare → keyframe-prompt → 外部エージェントがproposalを完成 → validate-only → register → draft prompt → 実本文 → check → 必要なreview-dialogue → 明示approveを実CLIで行う。
- 設定なしのdefault-onと登録前の停止も確認する。Pythonの合成JSON fixtureだけを外部エージェント評価と呼ばない。
- 既存API以外に有料モデルAPIを呼ばない。レビュー主体は実際の `agent` とIDを記録し、人間の承認とはしない。
- baselineと素材を使った本文は同じ短い場面条件で記録するが、少数の目的別例は一般的な改善を立証しない。逐語転記や心理描写数を合格条件にしない。

## ケース

| ケース | 短い入力 | 期待する読み・禁止事項 |
|---|---|---|
| 1: 誤解から返し方が変わる | ミラは鍵をなくした。レンの「いつ気づいた？」を責める問いに聞き違えかける。 | 不確かな受け止めが言い訳の撤回・返答の選び直しに効く。レンの本心を事実化しない。 |
| 2: 台詞への暗示 | 渡し舟が出る前に、約束を避けていた人物が条件を確かめ直す。 | 解釈を直接説明しなくても台詞の語順・留保・問い返しで変化が伝わる。全発話に心理を足さない。 |
| 3: 自然な地の文 | 音のしない作業場で、主人公が相手の置いた手袋に気づき、受け取り方を変える。 | 知覚→不確かな解釈→動きが近接三人称に馴染む。一人称素材の丸写しを避ける。 |
| 4: 例外的な短い橋渡し | 直前で警戒が示され、二人は無言で角を曲がるだけ。 | 台詞・地の文の両経路が不自然／冗長／テンポを損なう具体的理由がある場合のみ省略する。「短いから」だけの理由にしない。 |
| 5: POV・秘密・未来 | POV未指定、別人物だけの秘密、次章の予定を含む入力。 | POV不明では生成停止。author_contextやplanningをPOVの既知事実にしない。登録は意味的正しさの証明でないと区別する。 |
| 6: 局所増補 | 既存の短い本文に、素材の一部が既に台詞で反映されている。 | expandは必要な局所差分のみ。既に伝わる心理の重複説明や全文書換えをしない。 |

最小実施は1〜4のうち3〜4件で、暗示的台詞・地の文・具体的な例外省略を含める。5/6を未実施ならその旨を残す。

## 実施記録欄

各caseについて、次を別の検証記録へ複製して埋める。

- status: `not_run | run`
- 入力条件、POV、Length Band、project/scene ID:
- prompt/requestの保存先・generation ID:
- 外部エージェントが実際に作ったproposal:
- baseline本文と素材反映後の実本文:
- 正確な本文span（start/end char、引用。該当しない省略はその場面範囲）:
- 素材→台詞／地の文の対応、読者にどう読めるか、残る問題:
- omitの場合のdialogue_reason / narration_reasonの妥当性:
- checkの実status・warning・必要な会話レビュー:
- before/after比較（改稿があった場合。未記録の過去稿を検証済み履歴としない）:
- CLI exit/status、本文hash、approve主体:
- 候補外の短い台詞・地の文は「agentの自己評価」と明記:

機械check、素材登録、本文レビュー、ユーザーの作品採用判断を混同しない。
