# 日本語20万字対応 Implementation Plan

> 実装はタスク単位で失敗するテスト、最小実装、成功確認、差分レビューの順に進める。まず本計画をレビューし、合意後に着手する。この文書の作成段階では製品コードを変更しない。

**Goal:** 既存作品を壊さず、20万字の執筆・再開・改稿を、出典付きの長期記憶と一貫した検査・承認で支える。

**Architecture:** 既存CLIとscene txt / Markdown正本を維持し、runtime-firstを強化する。安全な保存・identity・状態・依存の共通基盤を先に整え、その上に20万字プロファイルと明示採用型の物語記憶を追加する。意味理解は外部エージェントが担当し、Pythonは検証・選択・状態管理に専念する。

**Tech Stack:** Python 3.8以上、標準ライブラリ、pytest、UTF-8のtxt/Markdown/YAML/JSON。

**Spec:** `../specs/2026-10-23-novel-200k.md`。対象コミットは `b8ea6f2a2e09dcbc51353953738e72e9305410fe`。

## Global Constraints

- 実装前の基準は87テスト成功。既存テストをskip・削除・閾値緩和して通さない。
- LLM API・ベクトルDB・追加の実行時依存は導入しない。
- 本文txt、`body.md`、ユーザーの未知フィールド・コメントを移行やhealthで破壊しない。
- `completed` は現行本文の機械検査pass。本文承認・意味記憶の採用とは別。
- 20万字の既定ゲートは160000字。既存scene typeの文字数帯は変更しない。
- 型表記はPython 3.8互換にする。以下の `dict` は設計書の明示スキーマを持ち、未知の必須versionは拒否する。
- `prompt_utils.py` の既存公開名は互換re-exportとして残す。今回触らない解析処理は移動しない。
- 新モジュールの低層から `prompt_utils` をimportしない。循環importをテストする。
- コミット・push・既存作品のapply移行は、この計画作成の範囲外。実装時のブランチと反映先は別途確認する。

## Review Focus

1. 改行形式・日本語パス・同一scene IDの複数ファイル: 既存ハッシュ互換を保ち、曖昧な対象を選ばない。Task 1・2。
2. 破損JSON・中断した保存・二重実行: 空の台帳で置換せず、復旧可能な状態を残す。Task 1・5・7。
3. 手編集のstate/outline・独自ゲート・レビュー後の変更: 誤推定して上書きせず、dry-runと期待ハッシュで停止する。Task 5。
4. 高類似の未来シーン・誤った人物知識・古い章要約: 選択前に排除し、staleを黙って採用し直さない。Task 7・8。
5. 記憶の欠損・必須文脈の予算超過・旧形式: 互換フローを維持し、重要情報を黙って捨てない。Task 8・10。
