## 実エージェントによる日本語4場面

同じ短い場面指示から、構造化中間表現なしの比較短文を独立に作成した。その後、別のエージェントが新方式の実CLIを使い、次の工程を実行した。

`prepare → keyframe-prompt → 外部生成 → validate-only → register-keyframes → draft prompt → 外部本文生成 → check → 必要な会話レビュー → agent approve → 完全export`

全4件は設定ファイルなしの標準有効、明示POVで実行した。短い検証用のLength Bandを使い、全長計画のゲートは無効にした孤立した実演である。3万字や20万字の完走試験ではない。レビュー担当はagentとして記録し、人間の承認と表示しない。

### 照合内容

最終コード候補 `db5c9e8ff3b7dd9f8b48d3a297f7a26657ef3191` でも4件を再検証・再exportした。既存の本文・承認・証跡のhashは変わらず、再登録・再承認は行っていない。

- 本文・check・承認のsource hashが一致する。
- keyframeのprompt／contract／registration hashと保存snapshotが一致する。
- checkと履歴承認の平坦な依存は有効。
- 完全exportは4件とも本文を保持し、未収録sceneは0。
- 中間表現からaccepted memoryへ自動登録された記録はない。

承認後はapproval ledgerが更新されるため、作成時runtime全体の依存はstaleになる。これは保存済み承認の無効化とは異なり、履歴承認とexportは有効なまま。新しい生成作業は同じsceneを再prepareする。検証のために古いhashを現在値へ付け替えていない。

## 文章の比較

生成条件を伏せたA/Bを、別のエージェントが読んだ。判定は新方式を3件で選び（2件は小差）、地図の場面は優劣混在だった。

- 地図：新方式は受け止めから返答への転換が直接的。一方、比較短文にも人物の声や結びの良さがあり、総合優位は断定できない。
- 本：新方式は自分の希望を選び直す動機と返答がつながった。ただし、末尾の仕草など説明を重ねる余地が残った。
- 屋台：新方式は成立した落ちの後を比較的短く締めた。比較短文は落ちを追加問答で説明し直していた。ただし新方式にも冒頭描写の長さは残る。
- 資料：新方式は「褒められた」という読みから確認へ切り替える流れが明確で、確認後の重複問答が少なかった。ただし内面の先回り説明には削れる箇所が残った。

これは4つの設計済み場面に対するエージェント定性評価である。比較対象は旧版CLIの完全な統制再現ではなく、人間の選好・統計的改善・長編全体への有効性を示すものではない。内面描写を増やしたこと自体を成功とは判定しない。全文の比較、生成中間表現、CLI証跡、盲検評価は同時納品の検証資料に収録する。

## 残る制約

- 理由や解釈の形式・出典を検証しても、意味的に正しい・自然であることまでは機械保証できない。
- 会話候補の検出は全ての主観表現を網羅しない。地の文や短い応酬もエージェントが読む必要がある。
- 今回は長い過去記憶を持つ実小説の再執筆ではない。時点・POV境界の回帰テストと、長編実作での品質評価は別物である。
- 追加工程の費用・執筆時間、複数モデルでの再現性、作者による日本語の選好評価は未計測／未実施。

## 実装上の判断

- 新しい依存投影は対象selectorに限ってversion 3を追加し、既存version 1/2の解釈を変更しない。新selectorを増やす場合はversion対応を明示的に追加する必要がある。
- 文脈の採否レポートに必須かどうかの表示を追加した。既存項目を削除せず、参照元を予算内で保持したか確認できるようにした。
- 本機能と無関係な旧合成試験は、具体的な試験理由を付けて明示的にoffにした。新機能試験は設定不在のdefault-onを別途assertし、製品側の既定値をoffへ戻していない。
- scene runtimeを別の場所へコピーしただけでは新しい正本として扱わず、同じsceneのprepareをやり直す。鮮度保護のため、旧runtimeでの新規執筆・承認には同じsceneの再prepareが必要になる。一方、歴史的な承認済み本文の読込・exportは保持する。

独立レビューで報告された重要3件は再現テスト付きで修正し、追加の文字数予算・証跡削除／降格・登録中断後の再試行の境界も検証した。レビュー上の軽微な指摘を未修正として残した項目はない。文学的な制約・未評価事項は上記のとおり残る。
